ctm 使用指南

让两个 Claude Code 窗口互相发消息。下面是一条能直接照做的路径，三分钟跑通。

ctm 是什么？ 你平时开两个终端，各跑一个 claude，它们互相不知道对方存在。 ctm 给它们加一条通道：在 A 里说一句“问一下 B”，这句话会真的出现在 B 的输入框里。
为什么教程里是 node src/main.mjs new …，不是直接敲 claude？ 因为普通 claude 的输入框只连着你的键盘，别的程序写不进去。 要让 A 的话出现在 B 的输入框，B 的 claude 必须由一个“拿着它输入输出”的进程启动—— 这个进程就是 ctm。
所以 ctm new 不是替代 claude，它就是启动 claude，只是外面多包了一层。 你看到的界面、模型、斜杠命令，全都还是原来的 claude。

照做一遍 每步都给出真实输出

0
先确认环境 
cd D:/projects/claudecode-plugings/ctm
npm install
node src/main.mjs doctor

最后一行是 结论：通过 才继续。不是的话按提示修。

1
用 ctm 启动第一个 claude（终端 1） 
node src/main.mjs new web --cwd D:/projects/web --group dev
  • node src/main.mjs用 Node 运行 ctm；全局安装后这里就是 ctm
  • new开一个新的托管会话
  • web给这个会话起的名字，之后 /ctm:ask web … 用它
  • --cwd D:/projects/webclaude 在哪个目录工作，换成你自己的项目路径
  • --group dev放进 dev 组；两个会话的组名必须一样

它会启动一个真正的 claude。等状态变成 idle（通常 10～20 秒）， 这个窗口就“能收信”了。首次进入目录的信任提示会由 ctm 自动处理。

2
开第二个会话（终端 2） 
node src/main.mjs new api --cwd D:/projects/api --group dev

和第 1 步只有两处不同：名字是 api，工作目录换成另一个项目。 关键是 --group dev 两边要一样。组名就是通讯录， 不同组的会话互相看不见。

3
在 api 的窗口里发消息

直接对 claude 说人话就行：

帮我问一下 web 会话，接口地址是什么

AI 会自己调用 ctm_ask。你也可以用斜杠命令：

/ctm:ask web 接口地址是什么？
4
在 web 的窗口里看到消息 
❯ [来自会话 api，工作区 D:/projects/api · #7f3a1c2d] 接口地址是什么？

它变成 web 输入框里的一条用户输入并回车，web 的 AI 会正常回答。 注意：回答不会自动传回 api。需要 web 的 AI 用 /ctm:reply 7f3a1c2d ... 回复，或你再问一次。

到这里就够了。下面三块是“为什么”和“出问题怎么办”； 想先理解原理，直接跳到 内部怎么运作。

只需要记住三件事

谁能收信 只有用 ctm new 启动的会话。普通 claude 的输入框不在 ctm 手里， 别的进程写不进去。它只能发，不能收。
谁能发信 任意 Claude Code 会话，只要加载了 ctm 插件。 用 ctm new 启动的会话会自动加载；普通 claude 需要 claude --plugin-dir D:/…/ctm。
关窗口 ≠ 删除 按 Ctrl+C 关窗口只留下 pid=null，别的会话还能把它拉起来。 ctm kill 才会删掉注册信息，之后再也找不到它。

不想敲这么长的命令？ 三种启动方式，效果完全一样

A
仓库里直接跑（上面的教程用的就是这个） 
node src/main.mjs new api --cwd D:/projects/api --group dev

不用安装任何东西，但每次都要写全路径。

B
全局安装，之后用短命令 
npm install -g .
ctm new api --cwd D:/projects/api --group dev

在 ctm 目录里执行 npm install -g .，参数完全一样， 只是把 node src/main.mjs 换成 ctm。

C
让 claude 命令自己变成托管会话 
npm install -g .
ctm install-wrap

然后把 %USERPROFILE%\.ctm\bin 放到 PATH 最前面。之后照旧敲：

claude

ctm 会在背后接管它，会话名自动取当前目录名。 这是「什么都不用记」的方案，代价是要改一次 PATH。

这一步只需要做一次，而且完全可选——不做也能用 A 或 B。 只有换了 Node 安装、移动了 ctm 目录或重装过 ctm 时， 包装脚本里记录的绝对路径会失效，需要重新执行一次 ctm install-wrap。

七个最常见的误会

“B 一直显示忙，是不是卡死了？” 先看 ctm list：状态若是 needs-input，说明 claude 正在等你在那个窗口确认某个工具操作（比如写文件）。ctm 不会代你批准；确认后它才会继续，队列也会恢复投递。
“我敲 claude 就能进群聊了吧？” 发信可以。收信不行：普通 claude 的输入框不在 ctm 手里，没有通道能往里写。想收信，用 ctm new 启动。
“B 的窗口关了，消息就丢了吧？” 不丢。消息先落盘到 B 的收件箱；A 会按 meta.json 把 B 重新拉起来（连同原来的分组和启动参数），就绪后自动补投。实测 19～25 秒。
“那我先 ctm kill 掉 B，省点资源？” 别。ctm kill 会删掉 B 的注册信息，就再也找不到它了。省资源请直接关窗口或 Ctrl+C。
“分组是不是一道安全边界？” 不是。它约束的是会话之间的自动传播，同一用户仍然可以直接读写 ~/.ctm/。它防的是误串扰，不是防人。
“install-wrap 之后，所有 claude 调用都被托管了吧？” 只有交互式启动才托管。--version、-p、mcp 等非交互用法原样透传，脚本和 CI 不受影响。
“讨论频道会自动多轮吧？” 不会。每轮都要显式 start。自动多轮会让会话互相触发，token 成本不可控；节奏留在人手里。
